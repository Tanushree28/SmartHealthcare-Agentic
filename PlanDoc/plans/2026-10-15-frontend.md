# Frontend (Part B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web page that runs one case through the agent pipeline and shows each of the nine stages as it finishes. It ends with the report, a chat panel and a display-only outcome reveal.

**Architecture:**
- Everything for the page lives in the new top-level folder **`frontend/`**, as the user asked on 2026-10-15.
- Python (standard library only) does the work in three layers:
  - `frontend/app.py` holds the logic that can be tested without HTTP.
  - `frontend/server.py` is a thin `ThreadingHTTPServer` on 127.0.0.1. It streams stage events to the page as server-sent events.
  - `frontend/serialize.py` turns `orchestrator.StageEvent`s into JSON.
- The page itself is `frontend/static/` (HTML, CSS, JS): vanilla, no build step, nothing loaded from the internet.

**Tech Stack:**
- Python 3.13 standard library (`http.server`, `json`, `threading`, `urllib.parse`, `webbrowser`), plus numpy, pandas and wfdb, which are already installed.
- Vanilla HTML/CSS/JS with `<canvas>`.

**Spec:** `PlanDoc/agentic_with_fe.md` §14 (screen, behaviour, endpoints, security) and §15 (errors). Part A is built (`PlanDoc/plans/2026-10-15-agents-end-to-end.md`).

## Global Constraints

- **No new dependencies.** No pip installs, no npm, no CDN, no web fonts.
- **Local only.**
  - The server binds `127.0.0.1` only; `make_server` refuses any other host.
  - Requests whose `Host` header is not `127.0.0.1:<port>` or `localhost:<port>` get 403. This stops other websites reaching the server through the browser.
  - No CORS headers.
- **Content-Security-Policy** on the page: `default-src 'self'`. No inline script and no inline `<style>`.
- **The agents are not changed.** `src/agentic` is used as-is. The outcome reveal lives in `frontend/outcome.py`; `src/agentic` never imports it, and it is never put into a case, a prompt or the chat.
- **Banner and honesty labels from §3 are visible on the page:**
  - the SIMULATED CASE banner;
  - held-out / trained-on tags on records;
  - a train/val/test tag on ICU stays;
  - the risk caveat;
  - "display only" on the cardiologist's labels and on the outcome;
  - the draft badge on rules;
  - Fusion: BLOCKED.
- **Saving:** nothing is written to disk by the server.
- **Tests:** they live in `tests/frontend/`, following the repository pattern (`tests/<module>/`, `pytest.ini` `testpaths = tests`). `pytest.ini` gains `pythonpath = src .` so `import frontend` works.
- **No commits.** PERMISSIONS.md requires the user's OK.
- **Window length:** 2 s minimum (enforced by `ecg_window`); 120 s maximum on the page, which keeps the stream under about 1 MB.

## Review Focus

1. **The stream must close cleanly so it is never repeated.** The browser's `EventSource` reconnects whenever a stream closes, which would re-run the case. The page must call `close()` on `done`, on `error` and in `onerror`. Checked in the browser checklist (Task 5).
2. **Bad query values** (`seconds=abc`, `seconds=500`, `peaks=x`, nothing chosen, an unknown stay) must give an `error` event with a plain message, never a 500. Tests: `test_parse_run_rejects_bad_values` and `test_run_reports_errors_as_events`.
3. **A client that disconnects in the middle of a stream** must not kill the server, which should keep answering. Test: `test_client_disconnect_mid_stream_keeps_server_alive`.
4. **A forged `Host` header, an oversized or invalid chat body, and unknown paths** (including `/../`) must be refused. Tests in `test_server.py`.
5. **The outcome must never reach the chat.** After a reveal, chat prompts still contain no outcome words. Test: `test_outcome_never_reaches_the_chat`.

### Task 1: Serialize stage events

**Interfaces:**

- **Produces:** `serialize.event(ev) -> dict`, where each event dict is shaped as follows:

| Stage | Keys |
|---|---|
| every event | `stage`, `name` |
| a skipped stage | `skipped` |
| 1 | `record{name,tag,note}`, `lead`, `fs`, `start_s`, `signal[float]` |
| 2 | `signal[float]` |
| 3 | `r_peaks[int]`, `source` |
| 4 | `n_input`, `n_classified`, `n_dropped`, `examples[[float]]` |
| 5 | `classes`, `called`, `scores[[float]]`, `r_peaks`, `display_only{truth,agree,of}` |
| 6, 7 | `findings[dict]` |
| 8 | `matches[dict]` |
| 9 | `banner`, `simulated`, `report{kind,text,model,note,attempts,seconds,problems[str]}` |

### Task 5: The page

**Required elements:**
- the banner;
- a controls form with record, start, length, stay and beat-source selects, plus **Run** and **Step ▸** buttons;
- the LLM status chip;
- nine stage cards;
- a "Fusion: BLOCKED" note;
- a **Reveal real outcome** button;
- a chat panel with a list, a form and a thinking timer;
- an error line.

**Behaviour, from spec §14:**
- **Run** reveals each stage as it arrives; **Step** holds stages until clicked.
- Stage ①/②/③ draw on an ECG-paper canvas.
- Stage ④ shows up to 8 beat windows.
- Stage ⑤ shows a coloured strip with model labels above and truth below; mismatches get a ring, and hovering a beat shows its scores.
- Stages ⑥/⑦/⑧ are lists with clickable IDs. Clicking an H-finding about runs highlights its beats.
- Stage ⑨ shows the report with an "AI-written, fact-checked" or "template" badge, and the reasons in `<details>`.
- The chat is enabled after `done`.
- The `EventSource` is closed on `done`, `error` and `onerror`.
- Light and dark mode follow the system; the layout stacks at phone width.
